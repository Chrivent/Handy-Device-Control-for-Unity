Handy Device Control 0.3.0

이 저장소에서 개발하기
Unity Hub의 Projects → Add에서 이 저장소 안의 Development~ 폴더를 선택하고 Unity 6000.3.28f1로 연다.
Project 창의 Packages → Handy Device Control → Runtime에서 C# 코드를 수정하면 저장소의 Package/Runtime/ 원본에 바로 반영된다.
Assets/Scenes/ConnectionTest.unity를 열고 Play를 누르면 Wi-Fi와 블루투스를 테스트할 수 있다. 펌웨어 4 Wi-Fi 테스트에는 Assets/Settings/HandyConnectionSettings.asset에 개발용 Application ID를 입력하고, 실행 화면에서 기기의 Connection Key를 입력한다.
Window → General → Test Runner의 EditMode에서 Run All을 누르면 패키지와 연결 화면 테스트를 실행한다. 자동 테스트는 실제 기기 없이 실행할 수 있다.

다른 Unity 프로젝트에 설치하기
Unity 6000.3의 Window → Package Management → Package Manager에서 + → Install package from tarball을 선택하고 com.handydevicecontrol.unity-0.3.0.tgz를 연다.
로컬 소스를 설치하려면 Install package from disk에서 저장소의 Package/package.json을 선택한다. Git으로 설치할 때는 Install package from git URL에 https://github.com/Chrivent/Handy-Device-Control-for-Unity.git?path=/Package 를 입력한다.
게임 코드에 별도의 어셈블리 정의(.asmdef)가 있으면 Assembly Definition References에 HandyDeviceControl을 추가한다. C#에서는 다음 두 네임스페이스를 가져온다.

    using HandyDeviceControl;
    using System.Threading;

0.1.x에서 올릴 때는 패키지 ID가 바뀌므로 기존 패키지를 먼저 제거한 뒤 새 파일을 설치한다. 기존 게임 코드의 using과 이름으로 지정한 어셈블리 참조를 HandyDeviceControl로 바꾼다. GUID로 지정한 참조는 새 패키지에 자동으로 연결된다.
이전 버전에서 IHandyClient나 HandyBleClient의 StartTestAsync를 직접 사용했다면, 연결을 확인한 HandySession의 RunTestAsync()로 2초 시험과 정지까지 처리할 수 있다.

연결하기
Wi-Fi에서는 게임 개발자가 해당 게임의 Application ID를 설정하고 플레이어가 자기 기기의 Connection Key를 입력한다. 펌웨어 3은 REST API v2를 사용하며 Application ID를 비워도 된다. 펌웨어 4는 REST API v3를 사용한다.

    var session = new HandySession(new HandyApiClient(applicationId, connectionKey));
    await session.CheckAsync(cancellation);

Windows x64에서 블루투스를 선택하면 기기 검색 결과의 DisplayName을 목록에 표시한다. 플레이어가 선택한 항목으로 세션을 만든다. CancellationToken으로 검색이나 연결 확인을 취소할 수 있다.

    var devices = await HandyBleClient.ScanAsync(cancellation);
    // 목록에서 플레이어가 선택한 selectedIndex를 사용한다.
    var session = new HandySession(new HandyBleClient(devices[selectedIndex]));
    await session.CheckAsync(cancellation);

게임 이벤트에 연결하기
연결 세션을 필드에 보관하고 Unity 메인 스레드에서 호출한다. State가 Ready이면 동작을 시작할 수 있다. 연결 결과와 정지 결과는 Changed 이벤트와 State, Detail에서 읽는다.

    // 애니메이션 구간 진입. 기기 이동 범위의 30~65% 사이를 3초간 왕복한다.
    await session.RunStrokeAsync(minPercent: 30, maxPercent: 65, durationMs: 3000);

    // 별도의 장면 건너뛰기·일시정지·창 비활성화 이벤트에서 즉시 정지를 요청할 수 있다.
    await session.StopAsync();

RunStrokeAsync는 시간이 지나면 자동으로 정지를 요청한다. 시작·동작·정지 중에 들어온 새 왕복 요청은 건너뛴다. 다른 동작으로 전환하려면 StopAsync를 기다린 뒤 Ready 상태에서 시작한다. 연결 화면에서 짧은 동작을 점검할 때는 RunTestAsync()를 호출한다.
펌웨어 4 일반 BLE와 Wi-Fi는 왕복 속도 10%를 쓴다. 펌웨어 3 Wi-Fi와 레거시 BLE는 낮은 위치부터 한 번에 최대 0.5초인 이동을 보낸다. 남은 시간에 맞는 이동만 보내므로 짧은 구간에서는 첫 위치만 요청할 수 있다.
일반 BLE의 왕복 구간 설정은 펌웨어 4.0.15부터 사용한다. 레거시 BLE에는 모터 정지 상태를 읽는 명령이 없어 마지막 이동 시간이 지난 뒤 기기 응답을 확인한다.

연결 끊김과 종료
BLE를 쓰는 동안 Update에서 session.CheckBluetoothConnection()을 호출한다. StopUnconfirmed이면 기기의 정지를 직접 확인하고 같은 연결에서 StopAsync()를 다시 호출할 수 있다. 연결 방식은 플레이어가 선택한다.
씬 종료 전에 진행 중인 동작의 StopAsync()를 기다린다. 정지 결과를 확인한 뒤 세션을 Dispose()한다.

연결 화면
HandyDeviceControl.UI의 HandyConnectionPanel과 HandyConnectionSettings를 사용할 수 있다. 설정 에셋은 Create → Handy Device Control → Connection Settings에서 만들고 각 앱의 Application ID를 입력한다. 연결 패널은 같은 오브젝트의 UIDocument에서 credentials·bluetooth 영역, transport·devices 선택 목록, connection-key 입력란, state·detail·latency·profile 라벨, check·start·stop·scan 버튼을 이름으로 찾는다.
